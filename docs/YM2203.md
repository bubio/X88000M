# Yamaha YM2203 Technical Reference

## 概要

Yamaha **YM2203**（通称 *OPN* = FM Operator Type‑N）は、1980年代に登場した6チャンネルのサウンドICです。FM方式による3つの音声チャンネルと、Yamaha YM2149F互換の3チャンネルPSG（矩形波／ノイズ発生器）を統合しています。Wikipediaによれば、このICは12の演算ユニット（オペレータ）を持ち、3チャンネルの各チャンネルを4オペレータで構成し、オペレータ間の接続方法（アルゴリズム）を8種類から選択できる[^2]。各オペレータは13ビットのサイン波を発生し、ADSRエンベロープで音量を制御します[^2]。出力は外付けDAC（通常はYM3014）によりアナログ変換されます[^2]。PSGモジュールは3つの矩形波＋ノイズチャンネルと2つの汎用8ビットI/Oポートを持ち、General InstrumentのAY‑3‑8910/8912と互換です[^1]。

### 特徴

データシートに記載されている主な特徴は次のとおりです[^1][^2]。

- **3チャンネルのFM音源**：各チャンネルは4オペレータ構成。第3チャンネルは各オペレータの周波数を独立に設定できるため、通常の整数比ではない不協和倍音も生成可能[^2]。
- **3チャンネルの矩形波（SSG）＋白色ノイズ**：Yamaha YM2149Fの機能を内蔵し、AY‑3‑8910/8912ソフトウェアと互換[^1]。
- **2系統のプログラマブルタイマ**：タイマAとタイマBを搭載し、サウンド処理や割り込み生成に用いる[^1]。
- **8ビット汎用I/Oポート×2**：SSG部にあり、Z80などのマイクロプロセッサと直接接続できる[^1]。
- **内蔵クロック分周器**：入力クロックの分周比をレジスタで設定でき、FM部とPSG部でそれぞれ異なる分周数を指定する[^3]。
- **TTL互換入出力・単一5 V電源動作**：入力はTTLレベル互換で、5 V単電源で動作[^1]。電源電圧は4.75 V〜5.25 Vの範囲で規定され、入力高レベルは2.0 V以上、入力低レベルは0.8 V以下とされている[^3]。

### 内部構成

YM2203は、**FM音源ブロック**と**SSG（音源＋I/O）ブロック**を共有する**レジスタアレイ**、2つの**プログラマブルタイマ**、およびI/O制御回路から構成されます。FM音源ブロックではオペレータの出力を加算またはフィードバックすることで複数の調波成分を生成します。データシートではFM変調の数学的表現を示し、ベッセル関数を用いた周波数変調式を紹介している[^3]。第3チャンネルは特別モードを持ち、4オペレータそれぞれの周波数を独立設定できる点が他チャンネルと異なります。SSGブロックは、3つの矩形波チャンネルとノイズ発生器および2つの8ビットI/Oポートを持ち、音程生成や音量制御、エンベロープ生成を行います。

## レジスタ・マップ

OPNはCPUからのデータバスを介して2段階アクセス（アドレス指定→データ書き込み）を行います。次表はデータシート[^3]から整理した主要なレジスタ範囲と機能をまとめたものです。長文説明は本文で解説し、テーブルには簡潔なキーワードだけを掲載します。

| レジスタ範囲（16進） | 主な機能（概要） |

| $06 | ノイズ周波数設定[^3] |
| $07 | 入出力ポート制御／PSGとノイズ出力のON/OFF[^3] |
| $08 – $0A | PSG各チャンネルの音量設定。固定音量かエンベロープ適用を選択[^3] |
| $0B – $0C | PSGエンベロープの周期設定[^3] |
| $0D | PSGエンベロープ形状指定（アタックやリピートなど）[^3] |
| $0E – $0F | 8ビット汎用I/Oポート[^3] |

| $24 – $26 | タイマA/Bの設定値（$24と$25でタイマAの上位・下位、$26でタイマB）[^3] |

### タイマとモードレジスタ

タイマAおよびBはそれぞれ10ビットと8ビットのカウンタで、24H・25H・26Hに設定値を書き込んだ後、27Hのモードレジスタでロードおよび有効化を行う。27Hの各ビットは下記の意味を持ちます[^3]。

- **D7 (RESET B)** – タイマBをリセット（1でリセット、0で動作）。
- **D6 (RESET A)** – タイマAをリセット。
- **D5 (ENABLE B)** – タイマBカウント有効。
- **D4 (ENABLE A)** – タイマAカウント有効。
- **D3 (LOAD B)** – タイマBに設定値をロード。
- **D2 (LOAD A)** – タイマAに設定値をロード。
- **D1–D0** – 第3FMチャンネルのモード。`00`で標準（4オペレータ）、`01`〜`11`で第3チャンネルのオペレータを独立周波数モードにする。

タイマオーバーフロー時にはステータスフラグが立ち、CPUはステータスレジスタをポーリングして割り込み処理を行う。レジスタ0E/0FのI/Oポートは割り込み入力などにも利用できる[^3]。

### FM音色パラメータ

FM部分では各オペレータごとに以下のパラメータを設定することで音色を構成する。

- **Detune/Multiple ($30–$3E)**：基本周波数に対するわずかな周波数シフト（デチューン）と倍音比（1〜31倍）を設定[^3]。
- **Total Level ($40–$4E)**：オペレータの出力レベル（モジュレーション指数）[^3]。
- **Key Scale & Attack Rate ($50–$5E)**：鍵盤番号によるエンベロープ速度の変化率およびアタック段階の速度[^3]。
- **Decay Rate ($60–$6E)**／**Sustain Rate ($70–$7E)**／**Sustain Level & Release Rate ($80–$8E)**：エンベロープの残りの段階を定義[^3]。
- **Algorithm & Feedback ($B0–$B2)**：4つのオペレータをどのように接続するか（8種類）と自己フィードバック量を設定[^3]。

各チャンネルのキーコード（F‑number）は$A0〜$A2でチャンネル1、$A2〜$A4でチャンネル2、$A4〜$A6でチャンネル3を指定する[^3]。特別モード時は$A8〜$AEを利用し、各オペレータに独立したF‑numberを与える[^3]。

## 電気的仕様

データシートの絶対最大定格・推奨動作条件のうち、エミュレータ作成時に重要な項目を以下にまとめます[^3]。

- **電源電圧 (V<sub>dd</sub>)**：4.75 V min. ～ 5.25 V max.　単一5 V電源で動作[^1]。静電破壊を避けるため±0.3 Vを超える電圧を端子に加えないようにする[^3]。
- **入力高レベル (V<sub>IH</sub>)**：2.0 V min. ～ V<sub>dd</sub> max.（TTL互換）[^3]。
- **入力低レベル (V<sub>IL</sub>)**：–0.3 V min. ～ 0.8 V max.[^3]。
- **動作温度範囲**：0 ℃ ～ 70 ℃[^3]。保存温度範囲は–50 ℃ ～ 125 ℃[^3]。

## エミュレーション上の注意点

- **PSG互換性**：YM2203のPSG部はAY‑3‑8910/8912にソフトウェア互換であるため、多くの既存PSGエミュレーションコードを利用できる[^1]。ただし、8ビットI/Oポートが2系統ある点に留意する。
- **タイマ処理**：タイマA/Bのオーバーフローはステータスレジスタ内のFLAG A/Bビットで検出できる。CPU側でタイマ周期に応じてポーリングまたは割り込み処理を行う必要がある。
- **3チャンネル特殊モード**：モードレジスタの下位2ビットで第3FMチャンネルを独立周波数モードに切り替える。各オペレータのF‑number/ブロックは$A8〜$AEで別途設定する[^3]。
- **クロック分周**：FM部とPSG部で動作周波数が異なる。分周比レジスタ($2D～$2F)で設定し、PSG部は1～4、FM部は2～6が有効範囲[^3]。
- **出力**：YM2203自体はデジタル値を出力しない。アナログ出力端子（CHA, CHB, CHC）は外付けのDAC YM3014に接続する。PSG出力とFM出力はミキサ内で合成される。ノイズ発生器は矩形波チャンネルと独立したホワイトノイズを生成し、$06と$07で周波数・ON/OFFを制御する[^3]。

## FM レジスタのビット詳細

各 FM パラメータは「スロット (= オペレータ) ごと」または「チャンネルごと」に配置されています。以下のビット配置は YM2203 / OPN 系 FM 音源の標準的な仕様です。

| アドレス | 意味 |

### `$28` (Key On/Off) ビット詳細

```
 7   6   5   4   3   2   1   0
[OP4][OP3][OP2][OP1][ - ][CH2][CH1][CH0]
```

- `OP1`–`OP4`: そのオペレータをキーオン (1) するかキーオフ (0) するか
- `CH0`–`CH2`: 対象 FM チャンネル (0..2)。3 以上は YM2203 では無効
- 1回のレジスタ書き込みで指定チャンネルの 4 オペレータすべての キー状態を一括更新する

## オペレータのスロット順序 (1, 3, 2, 4 の罠)

`$30`–`$9E` の各レジスタは「16スロット (4チャンネル × 4オペレータ)」をリニアに並べた配置になっていますが、**スロット番号と オペレータ番号は素直な順番ではありません**。これは YAMAHA FM 音源全般に共通する有名な仕様で、エミュレータ実装で最も間違えやすい点です。

| アドレス下位 | オペレータの実体 |
|---|---|
| `$x0` | CH1 OP1 |
| `$x1` | CH2 OP1 |
| `$x2` | CH3 OP1 |
| `$x3` | (未使用 — OPNA では CH4 OP1) |
| `$x4` | **CH1 OP3** ← OP2 ではない |
| `$x5` | **CH2 OP3** |
| `$x6` | **CH3 OP3** |
| `$x7` | (未使用) |
| `$x8` | **CH1 OP2** ← OP3 ではない |
| `$x9` | **CH2 OP2** |
| `$xA` | **CH3 OP2** |
| `$xB` | (未使用) |
| `$xC` | CH1 OP4 |
| `$xD` | CH2 OP4 |
| `$xE` | CH3 OP4 |
| `$xF` | (未使用) |

**実装メモ**: レジスタ書き込みハンドラは `(reg & 0x03)` でチャンネル, `(reg >> 2) & 0x03` でスロットインデックスを取り、スロットインデックス `0,1,2,3` を **オペレータ番号 `1,3,2,4`** に変換するルックアップテーブルを必ず用意すること。

## F-Number と位相増分

YM2203 の各オペレータは 11-bit の **F-Number** と 3-bit の **BLOCK** で発音周波数が決まります。BLOCK は MIDI でいうオクターブ番号、F-Number はオクターブ内の音高です。

```
phase_increment_per_FM_clock = (F_Number << BLOCK) >> 1   ; 単位は 1/(2^20) 周期
```

つまり位相累算器を 20bit (もしくはそれ以上) で持ち、上位 10bit を sin テーブルのインデックスに使います (一般的な実装では位相テーブル 1024 × エンベロープ振幅と組み合わせる)。

連続周波数として表すと:

```
f_out [Hz] = master_clock / (PRESCALER * 6 * 24)   * (F_Number / 2^20) * 2^BLOCK
```

PC-8801 で使われる典型的な値は:

- `master_clock` = 3.9936 MHz (3.5795 MHz の場合もある — モデル依存)
- `PRESCALER` = `$2D` 系で設定 (FM 部のプリスケーラは 6 がデフォルト)

つまり 1 FM クロックあたりおよそ `3993600 / 6 / 24 ≈ 27733 Hz` でオペレータが回ります。サウンド出力サンプリング (44.1 kHz) に変換するには、フラクショナル累積器 (位相累積器とは別) で「FM 1サンプルを何個分の出力サンプルに引き伸ばすか」を管理します。

## エンベロープ・ジェネレータの段階

各オペレータは独立した 4 段エンベロープを持ちます。

```
KeyOn ─→ Attack(AR) ─→ Decay(DR) ─→ Sustain(SR) ─→ KeyOff ─→ Release(RR)
                                  ↑
                                  SL に達した時点で DR→SR に遷移
```

- **AR (Attack Rate, 5bit)**: エンベロープを最大値に近づける速度。AR の特性は **指数を1から引いた形** (`1 - exp(-t)`) — 最初は速く、最後は急に遅くなる exponential approach。一般的な近似は `delta = (env >> 4) + 1`
- **DR (Decay Rate, 5bit)**: AR で最大に達したあと、SL まで線形に減衰させる速度
- **SL (Sustain Level, 4bit)**: DR から SR への遷移点 (0=ほぼ最大、15=完全減衰の特殊値)。Manual Table 2-7 より bit 重み D7=24 / D6=12 / D5=6 / D4=3 dB なので **1 step = 3 dB**。SL=15 (D7..D4 全 1) のみ特例で 93 dB
- **SR (Sustain Rate, 5bit, = D2R)**: SL 到達後、ノートが続いている間も減衰し続ける速度。SR=0 のときは「真の sustain」で envelope は停止する (= ピアノなどの長押し用)
- **RR (Release Rate, 4bit)**: KeyOff された後の減衰速度。**実効 5-bit 値**は `(RR << 1) | 1` (1..31)
- **KS (Key Scale, 2bit)**: 高音ほどエンベロープを速くする補正 (= **KSR**)
- **TL (Total Level, 7bit)**: エンベロープ出力に常時加算される減衰量 (0=減衰なし、127=実質ゼロ)。**1 step = 0.75 dB**

#### Effective rate (AR/DR/SR と RR で式が異なる)

```
; YM2608 application manual page 25 / Table 2-8 より:
;   N4 = F11                                    ; F-Num bit 10
;   N3 = F11·(F10+F9+F8) + !F11·F10·F9·F8       ; F-Num の Boolean 関数
;   KC = (BLOCK << 2) | (N4 << 1) | N3          ; 0..31 の 5-bit Key Code
;   Rks = KC >> (3 - KS)                        ; KS=0 で最大シフト (= 0..3)
;                                                 KS=3 で 0..31 がそのまま

AR / DR / SR (5-bit field):
    if field == 0:
        rate = 0   ← envelope 停止 (Rks は加算しない)
    else:
        rate = min(63, 2 * field + Rks)

RR (4-bit field):
    ; 4-bit 値の実効 5-bit は (RR<<1)|1 = 1,3,5,..,31
    ; これを Manual の Rate=2R+Rks に当てはめると:
    rate = min(63, 2 * ((RR << 1) | 1) + Rks)
        = min(63, 4 * RR + 2 + Rks)
```

> **重要な罠**: AR/DR/SR の **field=0 を `2*0 + KSR` と扱ってはいけない**。
> field=0 のときは KSR を加算せず rate=0 (= envelope 停止) が正解。
> これを誤ると SR=0 のピアノ patch で「高音ほど早くサスティンが切れる」(KSR が大きいほど rate が大きくなり、何もしないはずの sustain phase が高音だけ進んでしまう) という現象が出る。
> 実装時のチェック箇所: `AdvanceFmEnvelope` の各 case の冒頭。

#### Envelope 値とアテニュエーション単位

エンベロープ値そのものは `0..1023` の **減衰量** (大きいほど無音に近い) として保持します。1 unit ≒ `96 dB / 1023 ≒ 0.094 dB` に相当します。

最終的に op 出力 = `sin_log[phase] + (env_level << 2) + (TL << 5)` で対数領域で和を取り、`exp_table` で線形に戻します。各シフト量は単位合わせ:
- `sin_log` は 1/256 octave 単位 (= 約 `0.0234 dB`)
- `env_level` は 0.094 dB → 1/256 octave に揃えるため `<< 2` (= ×4)
- `TL` は 0.75 dB → 1/256 octave に揃えるため `<< 5` (= ×32)

#### Sustain Level の env 単位換算 (二度間違えたところ)

YM2608 application manual Table 2-7 によると SL のビット重みは:

| bit | D7 | D6 | D5 | D4 |
|---|---|---|---|---|
| 減衰量 (dB) | 24 | 12 | 6 | 3 |

つまり **1 SL step = 3 dB**。env 値の 1 unit = 0.094 dB なので:

```
SL_threshold (env 単位) = SL * (3 / 0.094) ≈ SL * 32        (SL = 0..14)
SL_threshold = 992                                          (SL = 15、特殊値: 93 dB)
```

> **罠 (二段階)**:
> 1. 最初は `SL * 32` を使っていたが、ピアノ patch のサスティンが小さく聞こえたので「6 dB step だ」と誤解して `SL * 64` に変更してしまった
> 2. その後 manual を直接読んで Table 2-7 で 1 step = 3 dB と確定 → `SL * 32` に戻した
>
> 教訓: 聴感だけで「半分しかない/倍ある」と判断すると逆方向に倍違いの修正をして二倍迷う。一次資料を最初から見るべき。

## SSG-type Envelope Control ($90-$9E、Manual 2-5-2)

通常の ADSR エンベロープを越えて、SSG 風の繰り返し波形でオペレータ env を駆動する FM 専用機能です。**SSG (PSG) 部の `$0B-$0D` envelope generator とは無関係**です (名前が紛らわしいですが、SSG-EG はあくまで FM オペレータ側の機能で、レジスタも `$30-$9E` の operator block 内にあります)。

PMD など PC-88 の sound driver で **ピアノ・撥弦楽器・ベル系の音色** に多用されます。modulator の env を周期的に reset することで、自然な減衰サイクル感 (撥弦の繰り返し的減衰) を作るのが主な用途です。

### レジスタ形式 ($90-$9E)

```
D7 D6 D5 D4 | D3   D2  D1  D0
/  /  /  /  | EN | Att Alt Hold
```

- **EN (D3)**: 1 で SSG-EG 有効、0 で無効 (= 通常の ADSR)
- **Att (D2)**: KeyOn 時の初期極性。0=通常 (env が増加 = 減衰)、1=反転 (env が増加 = 上昇に見える)
- **Alt (D1)**: 1 で「終端で反転」(三角波系)、0 で「同方向で繰り返し」(鋸歯系)
- **Hold (D0)**: 1 で「終端で固定」、0 で「終端で繰り返し」

### 8 種波形 (D3=1 必須、表は D3..D0)

| No | D3..D0 | 形状 | 用途例 |
|---|---|---|---|
| 0 | 1000 | 鋸歯下降 (繰り返し ↘↘↘↘) | 撥弦・ピアノ modulator |
| 1 | 1001 | 1 回減衰 → silence で hold | 通常 ADSR と同等の単発 |
| 2 | 1010 | 三角 (↘↗↘↗ alternating) | ビブラート的 |
| 3 | 1011 | 1 回減衰 → peak で hold | 後半の長尾 |
| 4 | 1100 | 鋸歯上昇 (繰り返し) | リバース系 |
| 5 | 1101 | 1 回上昇 → peak で hold | スウェル系 |
| 6 | 1110 | 三角 (↗↘↗↘ alternating) | 上昇先行ビブラート |
| 7 | 1111 | 1 回上昇 → silence で hold | 単発リバース |

### 実装の要点

1. **AR は 1F (= 31, 即時 attack) を前提**: Manual には「AR を 1F に設定してください」と注記されています。チップが強制するわけではないので、software 側が患書きする必要があります。
2. **Inverted polarity フラグ**: KeyOn 時に `Att bit` で初期化、Alt 系の終端到達時にトグル。
3. **Render 時の effective env**: `effEnv = inverted ? (1023 - env_level) : env_level` を atten 計算に使う。
4. **Loop 動作**: env_level が 1023 (silence) に到達したら shape ルールに従って:
   - `Hold=1` → state=OFF で env=1023 を保持 (Alt=1 ならその前に反転を 1 回トグル)
   - `Hold=0, Alt=1` → 反転トグル + env_level=0 + state=DECAY で再開 (三角)
   - `Hold=0, Alt=0` → env_level=0 + state=DECAY で再開 (鋸歯)
5. **KeyOff 時**: もし inverted のままだったら `env_level = 1023 - env_level` で実 env に変換し、inverted を clear してから RELEASE に入る。これをしないと「inverted で env=1023 (= 聴感上 loud)」だった音が KeyOff しても release で減衰しなくなります。

### 罠

- **`$90-$9E` の case を「未実装」のままビルドしないこと**: 我々の最初の実装はこのレジスタを完全無視していたため、ピアノ patch の modulator が一発鳴って silence、carrier だけ残って「2-op のような薄い音」になっていました。**ユーザーが実機聴感で気付くまで数日かかりました**。
- **PSG の envelope generator ($0B-$0D) と混同しない**: 命名が紛らわしいですが、SSG-EG は FM オペレータの envelope を制御するもので、SSG (PSG) チャンネルの音量 envelope とは別物です。

## アルゴリズム (オペレータ接続の8パターン)

`$B0`–`$B2` の下位 3bit (ALGO 0..7) で、4 オペレータの接続トポロジを選びます。`OPx → OPy` は「OPx の出力を OPy の位相変調入力に加える」という意味です。出力 (キャリア) は ☆ で示します。

| ALGO | 接続 | 用途 |
|---|---|---|
| 0 | OP1→OP2→OP3→OP4☆ | 直列 4-op (シリアル接続。最も明るい音色) |
| 1 | (OP1+OP2)→OP3→OP4☆ | 並列モジュレータ → 直列 |
| 2 | OP1→(OP2+OP3)→OP4☆... | 厳密には OP2 と OP3 の出力を OP4 の入力に和算 |
| 3 | OP1→OP2 + OP3→OP4☆ | 2-op の組を 2 段直列 |
| 4 | (OP1→OP2☆) + (OP3→OP4☆) | 2-op を 2 系統並列 |
| 5 | OP1→{OP2☆, OP3☆, OP4☆} | 1 モジュレータ + 3 キャリア |
| 6 | OP1→OP2☆ + OP3☆ + OP4☆ | 1 直列ペア + 2 単独キャリア |
| 7 | OP1☆ + OP2☆ + OP3☆ + OP4☆ | 4 オペレータ全員がキャリア (PSG 的な加算合成) |

**フィードバック**: `$B0`–`$B2` の bit5–3 (FB, 3bit) は **OP1 のみ** に適用される自己フィードバック量です。OP1 の最新出力サンプルと 1 サンプル前の出力サンプルの **和** を取り、右シフトして OP1 の位相変調入力に加えるのが標準形式です。シフト量は operator output の bit 幅に依存します:

```
; 14-bit op output (peak ±8192, 本リポジトリの現行実装):
fb_mod = (op1_out_prev0 + op1_out_prev1) >> (10 - FB)   ; FB=1..7
fb_mod = 0                                              ; FB=0 (無効)
```

FB=7 (最大) で shift=3 → `sum / 8`。sum peak = 16384、fb_mod peak = 2048 = 4π phase units (Manual 規定値、1024-unit phase cycle の 2 周期分)。

> **罠 (解消済)**: 初期実装は op output を 13-bit (peak 4096) で作っていた時期があり、`>> (9 - FB)` が 4π を与える式だった。2026-04 の 14-bit 拡張時に `>> (10 - FB)` へ更新し、FB=7 → 4π の規定値を維持している。

### モジュレーションの feed-forward (オペレータ間)

ALGO 0..6 では、あるオペレータの出力を別のオペレータの位相変調入力に加える接続が使われます。標準的な YM2151/2203 実装では、operator output (signed 14-bit、`±8192` レンジ) を `>> 1` してから次のオペレータの 10-bit 位相インデックスに加算します。

```
mod_input = op_out >> 1                            ; 単一モジュレータ
mod_input = (op_out_a + op_out_b) >> 1             ; ALGO 1 のように 2 op が並列で 1 carrier に入る場合
                                                     (sum を取ってから shift)
```

この `>> 1` スケーリングの意味: max modulator output = 8192 を shift すると 4096 phase units、これは phase cycle (1024 units) の 4 周期 = **8π** に相当し、Manual 規定の「max 変調深度 8π」と一致します。

> **本リポジトリの実装経緯 (2026-04)**:
> 1. 初期: op output を 13-bit (peak 4096) で生成 + modulation を `>> 1` → 実効変調深度 4π (標準の半分)。「貧相・鈍い」音色になっていた。
> 2. 途中: op output を `>> 1` せずそのまま (`>> 0`) に変更して聴感改善したが、その後 op output を 14-bit (peak 8192) に拡張したタイミングで変調深度が 16π (標準の 2倍) になり「明るすぎ・荒い・倍音が強すぎる」状態に。FFT で fmgen との 2 倍音/3 倍音差を確認。
> 3. 現行: op output 14-bit + modulation `>> 1` の組合せで 8π (標準) に復帰。fmgen との A/B で今までで最良の一致を得た。
> feedback と違って algo 7 (4 carriers 加算のみ) は modulation path が無いので影響を受けない。

### F-Number high の latch 動作

`$A4`–`$A6` (BLOCK + F-Num MSB) と `$A0`–`$A2` (F-Num LSB) は、**チップ内部の latch を経由して同期書き込みされる** 仕様です:

- `$A4`–`$A6` への書き込み → 内部 latch に保持されるだけ。チャンネル状態は **更新されない**
- `$A0`–`$A2` への書き込み → latch の値と新規 LSB が **同時に** チャンネル状態にコミットされる

そのため、ソフトウェアは必ず **`$A4` → `$A0` の順** で書き込む必要があります (逆順に書くと意図しない F-Num/BLOCK の組み合わせが瞬間的に有効になる)。

エミュレータ実装は、`$A4`–`$A6` の書き込みを per-channel の `m_abtFmFnumLatch[]` に保持し、`$A0`–`$A2` 書き込み時にそれと組み合わせて wFnum/btBlock を更新する必要があります。CH3 special mode 用の `$AC`–`$AE` / `$A8`–`$AA` も同じパターンです。

> **罠**: 「`$A4` 書き込みのときに即 wFnum 上位を更新し phase increment を再計算する」素直な実装をすると、`$A4` 書き込み直後 〜 `$A0` 書き込みまでの間 (Z80 の数命令分) に **誤った F-Number で位相が進む** ため、ノート切り替わり時に短いポップ/グリッチが入ります。

## SSG 部 (PSG) の実装メモ

YM2203 の SSG 部は **AY-3-8910 / YM2149 と完全互換** です。

### レジスタ詳細

| アドレス | 内容 |
|---|---|
| `$00`/`$01` | CH A トーン周期 (12bit、`$00`=下位 8bit, `$01`=上位 4bit) |
| `$02`/`$03` | CH B トーン周期 |
| `$04`/`$05` | CH C トーン周期 |
| `$06` | ノイズ周期 (5bit) |
| `$07` | ミキサ: bit0..2 = トーン enable (0=有効), bit3..5 = ノイズ enable (0=有効), bit6/7 = I/O port 方向 |
| `$08`/`$09`/`$0A` | CH A/B/C 振幅: bit0..3 = 振幅 (4bit log), bit4 = エンベロープ使用フラグ |
| `$0B`/`$0C` | エンベロープ周期 (16bit) |
| `$0D` | エンベロープ形状 (4bit, 下記参照) |
| `$0E`/`$0F` | I/O ポート A/B (8bit、PC-8801 ではジョイスティックとカレンダーに使う) |

### トーン生成

各チャンネルのトーン周期 N に対して、出力周波数は **`f = SSG_clock / (16 * N)`**。ここで `SSG_clock` は SSG セクションへの入力クロック (master / prescaler_psg)。

> **実装上の注意 (本リポジトリの罠)**: データシートの "16" は "TP は **フル波形周期** を `SSG_clock/16` 単位で表す" という意味であり、内部カウンタの分周値そのものではありません。実装する際は内部カウンタを **`SSG_clock/4`** で動かし、reload = TP で半周期ごとに出力反転すると、結果として `f = (SSG_clock/4) / (2*TP) = SSG_clock / (8*TP)` … *ではなく* … 実は **PC-88 SSG 系の慣習では `f = SSG_clock / (8*TP)` を使う** ようです。実際の PC-88 BGM のピッチと一致させるには、内部カウンタを `SSG_clock/4` で動かし reload = TP とする (= 結果的に `f = SSG_clock/(8*TP)`、データシートの literal な "16" の倍速) のが正解でした。理由は不明ですが、複数の PC-88 系エミュレータがこの慣習に従っています。

PC-8801 における SSG クロックはプリスケーラの設定に依存しますが、典型的には `master_clock / 4 = ~1.0 MHz`。実効的な内部カウンタ rate は `~250 kHz` (= SSG_clock/4)。

### ノイズ生成

17-bit LFSR で実装します:

```
bit_out = LFSR & 1
new_bit = ((LFSR >> 0) ^ (LFSR >> 3)) & 1   ; XOR feedback at taps 0, 3
LFSR = (LFSR >> 1) | (new_bit << 16)
```

LFSR 進行のレートは公称 `f_noise = SSG_clock / (16 * NoisePeriod)` (N=0 のときは 1 として扱う)。トーンと同じ理由で、内部カウンタを `SSG_clock/4` で動かす実装では reload = `2 * NoisePeriod` で **絶対 LFSR 速度をデータシート公称値と一致させる** ことができます。

### 4-bit ボリューム → 線形振幅テーブル

SSG の音量レジスタは 4-bit log で、YM2149 / AY-3-8910 のデータシートでは **隣接レベルの電圧比 = 0.707 (= 1/√2)** と規定されています。これは **3 dB / step** に相当し、16 レベルで合計約 45 dB のダイナミックレンジになります。線形値は次のように**自前で計算**します:

```c
// vol[0] = 0
// vol[i] = max * 10^((i - 15) * 3.0 / 20)   for i = 1..15
```

各レベルの目安:

| Level | dB from max | linear (max=8000) |
|---|---|---|
| 15 | 0       | 8000 |
| 14 | -3      | 5662 |
| 13 | -6      | 4007 |
|  7 | -24     | 504  |
|  4 | -33     | 179  |
|  1 | -42     | 64   |
|  0 | -∞      | 0    |

> **重要 (実装上のハマりどころ)**: 一部のドキュメントは「1.5 dB / step」と書きますが、これは **32 ステップ envelope generator** の方の値です。16-level vol register は **3 dB / step** が正しい値で、これを取り違えると vol=4 のような小音量レベルが大きすぎて聴こえ、PMD 系 BGM で「ノートが長すぎる/伸びている」ような印象になります (実際にこの罠にハマりました)。

(具体的な定数表は他者のコードからコピーせず、上記の式から `Initialize()` 内で生成すること)

### 32-step エンベロープ → 線形振幅テーブル

エンベロープの 32 レベルは 5-bit DAC 相当で、ボリュームの 16 レベルの 2 倍の解像度です。1 ステップは **1.5 dB**:

```c
// env[0] = 0
// env[i] = max * 10^((i - 31) * 1.5 / 20)   for i = 1..31
```

### エンベロープのタイミング (もう一つの罠)

YM2149 データシートには `f_envelope = fc / (256 × EP)` という式があります。これは **「32 ステップを 1 サイクルとした周期」** であって、**1 ステップあたりのレートではありません**:

- 1 サイクル = 256 × EP / fc 秒
- 1 ステップ = (256 × EP / fc) / 32 = **8 × EP / fc 秒**
- 1 ステップあたりのレート = fc / (8 × EP)

内部カウンタを `SSG_clock/4` で動かす実装の場合、env counter の reload は単に **EP** (倍率なし) で正解。`EP × 32` などにすると 32 倍遅すぎてドラムやスタッカートが減衰しきらず連続音化します (実際にハマりました)。

### エンベロープ形状

`$0D` の下位 4bit `[CONT][ATTACK][ALTERNATE][HOLD]` の組み合わせで 8 種類のパターンが選べます (上位 4 通りは下位 4 通りと同じ動きをします)。

| 形状値 | 動作 |
|---|---|
| `0..3` (CONT=0) | 1回だけ下降 (`\___`) |
| `4..7` (CONT=0, ATT=1) | 1回だけ上昇後ゼロ (`/___`) |
| `8`  (`\\\\`) | 鋸歯下降を繰り返す |
| `9`  (`\___`) | 1回下降してホールド (= 0..3 と同じ) |
| `10` (`\/\/`) | 下降→上昇を繰り返す |
| `11` (`\¯¯¯`) | 下降してから最大値ホールド |
| `12` (`////`) | 鋸歯上昇を繰り返す |
| `13` (`/¯¯¯`) | 上昇してから最大値ホールド |
| `14` (`/\/\`) | 上昇→下降を繰り返す |
| `15` (`/___`) | 上昇してから 0 にホールド (= 4..7 と同じ) |

## CH3 特殊モード

`$27` のビット 6/7 で CH3 を「特殊モード」にすると、CH3 の 4 オペレータそれぞれに**異なる F-Number / BLOCK** を与えられるようになります。これにより不協和な倍音や非整数比の音色を作ることができます。

- `$27` D7,D6 = `00`: 通常モード
- `$27` D7,D6 = `01`: CSM。Timer A overflow ごとに CH3 を自動 key-on する
- `$27` D7,D6 = `10` / `11`: effect sound mode。オペレータ別 F-Number は使うが、CSM の Timer A 自動 key-on は行わない
- 通常モード: CH3 の全 4 オペレータは `$A2` (低位) / `$A6` (高位) で同じ F-Number を共有
- 特殊モード:
  - OP4 → `$A2` / `$A6` (通常の場所)
  - OP1 → `$A9` / `$AD`
  - OP2 → `$AA` / `$AE`
  - OP3 → `$A8` / `$AC`

YM2608(OPNA) の上位ポート側 CH6 も同じ対応で、`$A8`/`$AC` は OP3、`$A9`/`$AD` は OP1、`$AA`/`$AE` は OP2 に割り当てます。

## PC-8801 における YM2203

- **接続 I/O ポート**: `$44` (アドレス / ステータス読み出し), `$45` (データ書き込み / 読み出し)
- **マスタクロック**: 約 3.9936 MHz (機種により若干異なる)
- **割り込み**: タイマ A/B のオーバーフローをステータスレジスタで読み取り、Z80 INT に接続
- **ステレオ**: YM2203 はモノラル出力のため、SDL3 ステレオストリームへ流す際は L/R に同じサンプルを書く

## ステータスレジスタ

`$44` を読み出すと取得できる 8bit:

| bit | 意味 |
|---|---|
| 7 | BUSY (書き込み直後の少しの間 1) |
| 6..2 | 0 (未使用) |
| 1 | TIMER B オーバーフロー (1 で発生中、`$27` の RESET B でクリア) |
| 0 | TIMER A オーバーフロー (1 で発生中、`$27` の RESET A でクリア) |

## 仕様だけでは決まらない部分 (= スクラッチ実装の限界)

Yamaha が公開した YM2203 / YM2608 アプリケーションマニュアルおよび本ドキュメントの式に基づいて実装すれば、「FM らしい音」「音楽として聴ける」レベルには到達できます。**ただし fmgen / ymfm 等と区別がつかないレベルで一致させるには、公開仕様だけでは情報不足** です。以下は公開仕様にない (= reverse engineering / chip decap でしか得られない) 値:

| 項目 | 公開仕様での扱い | 完全一致のために必要な情報源 |
|---|---|---|
| **Sin / Exp テーブルの量子化値** | 数式 (`-log2(sin)`, `2^-x`) は明記 | 実機の固定 LUT 値 (decap) |
| **Envelope rate の (shift, add) 分解と離散イベント発火タイミング** | 「rate 0..63 で速度が変わる」とだけ | rate selector LUT (decap) |
| **DT (Detune) テーブル** | 「DT 値で周波数が変わる」とだけ | 64 エントリの実数値テーブル |
| **Attack curve の正確な係数** | 「指数的に最大値に近づく」とだけ | curve LUT |
| **Operator output の bit 幅と各段の saturation** | データシートに明記なし | 14-bit signed + 各段 saturate (decap) |
| **Modulation feed-forward の正確な shift 量** | 仕様による定義なし | 標準は `op_out >> 1` |

これらは fmgen / Nuked OPN2 / ymfm / MAME などの decap 由来プロジェクトから引用するとライセンスが汚染されます。代替として、**Yamaha YM2608 アプリケーションマニュアル** (Yamaha 公式、当時のサウンドプログラマ向けに公開された資料) に DT テーブル・envelope rate の (shift, add) 分解表が記載されているはずで、これは **公知の仕様情報** として参照可能です。

参考になる二次資料 (引用元として一次資料を辿る用):
- [lipoyang.hatenablog.com](https://lipoyang.hatenablog.com/entry/20131112/p1) — 「YM2203 FM音源レジスタ設定の要約」。Yamaha YM2203/YM2608/YM3438 のデータシート及び PC-9801-86 ユーザーズマニュアル / Oh!MZ 誌を一次資料として要約したブログ記事。**DT テーブルや envelope rate の数値表もまとまっている**。本文は本人が「実機検証していない」と断っているので、最終的には引用元 (Yamaha 公式マニュアル) を直接参照して確認するのが望ましい

スクラッチ実装でも到達可能なこと:
- 正しい音程
- ADSR エンベロープがそれっぽく動く (持続音・打楽器・スタッカートが区別できる)
- アルゴリズム接続が音色構造を変える効果が分かる
- BGM がメロディとして聴き取れる

スクラッチ実装で到達不能なこと:
- fmgen と区別がつかない音色一致
- 特定の FM ピアノ patch などの細かな質感の再現
- chip-accurate なエンベロープ段差感

## 比較用レジスタログと WAV 再レンダリング

他エミュや実機録音に近づけるためのブラックボックス比較用に、YM2203 のレジスタ書き込みを sample frame 単位で CSV 化し、`PC88Opna` 単体で同じログを WAV に再レンダリングできるようにしている。

### ログ取得

`X88_OPN_LOG` に出力先 CSV を指定して X88000M を起動すると、YM2203 への書き込みが次の形式で記録される:

```sh
X88_OPN_LOG=/tmp/opn.csv ./build/X88000M.app/Contents/MacOS/X88000M
```

CSV 形式:

```text
frame,event,address,data
12345,D,A4,22
12345,D,A0,58
12348,D,28,F0
```

- `frame`: その書き込みが発生した時点の出力 sample frame
- `event=D`: 通常の data write。再生時は `WriteAddress(address)` → `WriteData(data)` として扱う
- `event=A`: address write だけで副作用を持つ `$2D-$2F` prescaler 書き込み。再生時は `WriteAddress(address)` のみ

### WAV 再レンダリング

CMake で `opn_log_render` がビルドされる。取得した CSV を同じ `PC88Opna` 実装へ流し込み、stereo 16-bit PCM WAV を生成する:

```sh
cmake --build build --target opn_log_render
./build/opn_log_render /tmp/opn.csv /tmp/opn.wav --fm-only --fm-ch 1 --tail-sec 3
```

主なオプション:

- `--fm-only`: SSG をミュートして FM だけ出力
- `--ssg-only`: FM をミュートして SSG だけ出力
- `--fm-ch 1..3`: 指定 FM チャンネルだけ solo
- `--ssg-ch 1..3`: 指定 SSG チャンネルだけ solo
- `--rate 44100`: 出力 sample rate
- `--base-clock-mhz 4`: YM2203 master clock MHz
- `--tail-sec N`: 最後の書き込み後に N 秒ぶん余韻をレンダリング

この流れで「同じゲーム区間の他エミュ録音」と「X88000M のログ再レンダリング WAV」を比較し、まず envelope の包絡線、次に FFT / スペクトログラムの倍音比を合わせていく。

### WAV 比較とヒット単位解析

手動録音は開始タイミングがずれるため、`opn_compare_wav.py` で RMS 包絡線ベースの自動整列を行う:

```sh
python3 tools/opn_compare_wav.py \
  /path/to/reference.wav /tmp/opn.wav \
  --candidate-channel 1 \
  --out /tmp/opn_compare.png \
  --spectrogram /tmp/opn_spectrogram.png
```

FM ドラムのように key-on ごとに音色が切り替わる素材は、`opn_analyze_hits.py` で `$28` key-on と直前の CH レジスタ状態からヒットを分類する:

```sh
python3 tools/opn_analyze_hits.py \
  /tmp/opn.csv /path/to/reference.wav /tmp/opn.wav \
  --fm-ch 3 --candidate-channel 1 \
  --offset-sec 7.05 --gain 2.33 \
  --out /tmp/opn_hit_groups.png
```

出力される `tail50/tail100/tail200` は key-on 後 50/100/200ms 時点で、ピークに対してどれだけ包絡線が残っているかを示す。candidate 側が小さければ、その音色では envelope が速すぎる。

### Envelope rate 実験ノブ

2026-05 の Scheme CH3 / YS Opening CH1 比較で、従来の envelope rate は FM percussion と持続音の減衰が速すぎることが分かったため、既定値を `0-35:0.20,36-63:0.12` 相当にしている。これは v1.0.2 時点の `shift=13` 近似に対する追加倍率で、低〜中 rate を 0.20x、高 rate を 0.12x にする。

比較実験を回すため、`BuildFmTables()` は次の環境変数を読む:

```sh
X88_FM_ENV_RATE_SCALE=0.30
X88_FM_ENV_RATE_BANDS='0-35:0.30,36-63:0.20'
X88_FM_DECAY_RATE_SCALE=0.8
X88_FM_SUSTAIN_RATE_SCALE=0.5
X88_FM_PERC_DECAY_RATE_SCALE=1.0
X88_FM_MOD_SCALE=1.10
X88_FM_MOD_SCALE_ALGO2=1.0
X88_FM_FB_SCALE=1.25
X88_FM_PHASE_RESET_ON_KEY=0
X88_FM_DT_SCALE=1.50
X88_FM_DT_APPLY_MUL=true
X88_FM_DT_MUL_WEIGHT=1.0
X88_FM_RELEASE_RATE_SCALE=1.0
X88_SSG_MIX_SCALE=0.5
X88_FM_MIX_SCALE=1.0
X88_ADPCM_MIX_SCALE=1.4
X88_RHYTHM_MIX_SCALE=1.4
X88_MASTER_VOLUME_MAX_GAIN=1.0
```

- `X88_FM_ENV_RATE_SCALE`: 全 rate の平均進行量に掛ける倍率
- `X88_FM_ENV_RATE_BANDS`: `first-last:scale` のカンマ区切り。指定 rate 帯だけ倍率を上書き
- `X88_FM_DECAY_RATE_SCALE`: DECAY state だけの追加倍率。既定値は 1.0
- `X88_FM_SUSTAIN_RATE_SCALE`: SUSTAIN state だけの追加倍率。既定値は 1.0
- `X88_FM_RELEASE_RATE_SCALE`: RELEASE state だけの追加倍率。既定値は 1.0
- `X88_FM_PERC_DECAY_RATE_SCALE`: `ALGO=4 / FB=7` の打楽器的パッチだけに掛ける DECAY 追加倍率。YS2 Opening CH3 のドラムで尾が残りすぎるため既定値は 1.5。1.0 で無効相当
- `X88_FM_MOD_SCALE`: operator 間 feed-forward modulation の倍率。厚み・倍音量の A/B 用
- `X88_FM_MOD_SCALE_ALGO0`〜`X88_FM_MOD_SCALE_ALGO7`: algorithm 別の modulation 追加倍率。YS Opening CH1 後半の ALGO2 音色に合わせ、ALGO2 の既定値は 0.95
- `X88_FM_FB_SCALE`: OP1 self-feedback の倍率
- `X88_FM_PHASE_RESET_ON_KEY`: 1 で key-on edge ごとに operator phase を 0 に戻す。StarTrader Opening の FM 3ch ドラムで低域の押し出しが改善したため既定値は 1。0 で旧 free-running phase 挙動
- `X88_FM_RETRIGGER_ON_KEY_WRITE`: 1 で既に key-on 中の `$28` 再書き込みでも ATTACK を再トリガする。通常のドライバは F-Number 更新中にも同じ key-on mask を再書き込みするため、既定値は 0
- `X88_FM_DT_SCALE`: detune offset の倍率。うねり・chorus 感の A/B 用
- `X88_FM_DT_APPLY_MUL`: 1 で DT offset を operator MUL に追従させるための重み処理を有効にする。既定値は 1
- `X88_FM_DT_MUL_WEIGHT`: DT が operator MUL に追従する量。既定値は 1.0。Scheme DeathWorld CH2 で full MUL-follow が必要なため、こちらを標準にする。0.0 で旧 fixed-offset 相当
- `X88_SSG_MIX_SCALE`: SSG セクションの最終ミックス倍率。2026-05 の FM 改善後は既定値 1.0。0.5 で旧「SSG 半分」挙動
- `X88_FM_MIX_SCALE`: FM セクションの最終ミックス倍率。FM/SSG バランス調整後の既定値は 1.6。1.0 で旧 FM レベル
- `X88_ADPCM_MIX_SCALE`: ADPCM セクションの最終ミックス倍率。既定値は 1.4
- `X88_RHYTHM_MIX_SCALE`: rhythm セクションの最終ミックス倍率。既定値は 1.4
- `X88_MASTER_VOLUME_MAX_GAIN`: SDL3 frontend の master volume 100 に対応する最終出力 gain。既定値は 2.0。1.0 で旧「100 = unity」挙動

旧 v1.0.2 近似 (`shift=13` のみ) と比較したい場合は次のように起動する:

```sh
X88_FM_ENV_RATE_BANDS='0-63:1'
```

### 1. Modulation 入力の attack curve バグ (修正済み)
- **症状**: ATTACK phase で env_level が一切減らない (notes が無音のまま)
- **原因**: `~op.nEnvLevel >> 4` を使っていた。signed の bitwise NOT で負値になり、ATTACK が逆方向に進んでいた
- **修正**: `(op.nEnvLevel >> 4) + 1` に変更

### 2. `m_nFmPhaseScaleX16` 未計算 (修正済み)
- **症状**: 全 FM op で phase_inc = 0 (位相が進まず無音)
- **原因**: `UpdateFmTickRate()` で `m_nFmTicksPerSampleX16` のみ計算し、phase scale を計算し忘れていた
- **修正**: `m_nFmPhaseScaleX16 = master * 65536 / (prescaler * 24 * sample_rate)` を追加

### 3. RR formula 4× too fast (修正済み — YM2608 manual で確定)
- 過去のバージョンに `((rr<<1)+1)*2 + ksr` (= `4*RR + 2 + KSR`、標準) があったが、当時の聴感判断で 「4× 速すぎる」と思って `(rr<<1)+1+ksr` に直してしまっていた
- YM2608 application manual page 30 で「Rate = 2R + Rks (R = 0 で Rate = 0)、ただし RR は R = (set value × 2 + 1)」と明記されており、結果 `Rate = 4*RR + 2 + Rks` が正規式と確定
- 修正: `(op.btRr << 2) + 2 + nKsr` に変更

### 4. AR/DR/SR=0 → rate=0 ルール忘れ (修正済み)
- **症状**: SR=0 (= 真の sustain) のはずの patch で、高音 (KSR が大きい) ほど早く音が消える
- **原因**: `nRate = field * 2 + KSR` だけを計算していたため、field=0 でも KSR が rate を進めてしまっていた
- **修正**: 各 case の冒頭で `if (op.btXR == 0) return;` を入れて停止
- **詳細**: 上記「Effective rate (AR/DR/SR と RR で式が異なる)」節を参照

### 5. SL の dB 換算 (二度間違えた、最終的に SL × 32 が正解)
- **第一次**: `SL × 32` を使っていた → ピアノ系 patch のサスティンが妙に小さく聞こえたので「6 dB step」と誤解して `SL × 64` に変更してしまった
- **第二次**: YM2608 application manual Table 2-7 を参照したところ、SL bits D7..D4 の重みは **24/12/6/3 dB** で、明確に 1 step = 3 dB と判明 (`SL × 32`)。SL=15 (D7..D4 全 1) のみ特例で 93 dB ジャンプ
- **修正**: `(op.btSl == 0x0F)? 992: (op.btSl * 32)` に確定
- **詳細**: 上記「Sustain Level の env 単位換算」節を参照

### 6. Modulation feed-forward depth (2 回曲がって最終的に 14-bit + `>> 1` に収束)
- **第一次症状**: 13-bit op output (peak ±4096) で modulation を `>> 1` にしていた → 実効 4π (標準の半分)、音色が「貧相・鈍い」
- **第一次修正 (暫定)**: ALGO 0..6 の modulation 入力を `>> 0` (shift せず) に変更 → 相対的に標準相当の変調深度
- **第二次症状**: 2026-04 に op output を 14-bit (peak ±8192) に拡張した際、`>> 0` のままだったため実効 16π (標準の 2倍)。FFT 比較で 2倍音/3倍音が fmgen より明らかに強く、「明るすぎ・荒い」音色に
- **第二次修正 (確定)**: ALGO 0..6 の modulation 入力を `>> 1` に戻す。これで 14-bit op × `>> 1` = 8π (Manual 規定値)。ユーザー聴感で「今までで一番 fmgen に近い」と確認
- **詳細**: 上記「モジュレーションの feed-forward」節を参照

### 7. Feedback shift (op output bit 幅に合わせて 2 回更新)
- **症状**: フィードバックが弱く、「ベース」「ベル」系の patch で力強さが出ない
- **初期の誤り**: 13-bit op 時代に `>> (10 - FB)` を使っていた。13-bit peak 4096 のとき標準は `>> (9 - FB)` (FB=7 → shift=2 → 4π)
- **第一次修正**: `>> (9 - FB)` に変更
- **14-bit 拡張後**: op peak が 8192 になったため、同じ 4π を保つには `>> (10 - FB)` が再び正解 (FB=7 → shift=3 → 16384/8 = 2048 = 4π)。現在は 14-bit 版として `>> (10 - FB)` で確定
- **詳細**: 上記「フィードバック」節を参照

### 11. Envelope rate が fmgen より約 4x 速い (一次近似で修正)
- **症状**: ピアノ系 patch (DR=7+KSR=6=rate20) の decay が 93ms 程度で、fmgen の ~340ms に比べて明らかに速い。減衰が切れる前に次の音が重なる場面で音色の印象が別物になる
- **原因**: `BuildFmTables()` の envelope rate 式 `shift = 11 - (rate >> 2)` が全 rate で 3〜4x 速い設定だった。decap 由来の正確な rate-selector LUT (ymfm/fmgen) は本リポジトリでは参照禁止
- **修正**: 一次近似として一律 `shift = 13 - (rate >> 2)` に変更 (4x 低速化)。ピアノ decay が ~370ms となり fmgen 近似に。rate=0 の envelope 停止ルールはそのまま維持
- **限界**: sustained pad 系や release 系で個別 rate の fit はまだ経験的。decap LUT 相当の精度には届かないが、聴感上は十分近い

### 12. Operator output の 14-bit 拡張 (#6, #7 と連動)
- **症状**: 13-bit (peak 4096) では Manual 規定の modulation depth (max 8π) と feedback (FB=7 で 4π) を同時に満たすスケールが取れず、どちらかが標準の半分になっていた
- **修正**: `BuildFmTables()` の exp table peak を 4096 → 8192 に拡張 (14-bit signed `±8192`)。これに合わせて modulation `>> 1` (8π)、feedback `>> (10 - FB)` (4π) の両方が正規値になる
- **注意**: 出力合成段でも peak レンジが倍になるため、mixer 側のヘッドルームを確認すること (現状は最終段で飽和クリップしており問題なし)

### 8. F-Number high register の latch 未実装 (修正済み)
- **症状**: ノート切り替わり時に短いポップ/グリッチ
- **原因**: `$A4`–`$A6` 書き込み時点で wFnum 上位を即更新し phase increment を再計算 → 次の `$A0`–`$A2` 書き込みまでの間、誤った F-Num/BLOCK の組み合わせで位相が進んでいた
- **修正**: `m_abtFmFnumLatch[]` (および CH3 special mode 用 `m_abtFmCh3FnumLatch[]`) を追加し、`$A4`/`$AC` 系は latch のみ、`$A0`/`$A8` 系で latch + LSB を atomic に commit
- **詳細**: 上記「F-Number high の latch 動作」節を参照

### 9. KSR 計算式の Note 幅が半分だった (修正済み — YM2608 manual で確定)
- **症状**: KS=3 の patch でも実機より KSR が小さく、高音 / 低音の env 速度差がほとんど出ない
- **原因**: `nNote = (Block << 1) | (FNum bit10)` で Note を 1 bit に丸めていた。正しくは Note は 2 bit (N4, N3) で、`KC = (Block << 2) | (N4 << 1) | N3` で 0..31 のフルレンジ
- **修正**: YM2608 application manual page 25 の式に従って `N4 = F11`, `N3 = F11·(F10+F9+F8) + !F11·F10·F9·F8` を実装し、`Rks = ((Block << 2) | (N4<<1) | N3) >> (3 - KS)` に変更
- **検証**: Table 2-8 の KS=3 行で Block 0..7 の各 Note について 0..31 が出ることを確認

### 10. Detune テーブルが自前近似だった (修正済み — YM2608 manual の表を採用)
- **症状**: DT による chorus 効果が極小で、実機 Ys 等で「合奏感」が出ない
- **原因**: BuildFmTables() で `r * (1 + (v >> 3))` という monotonic な簡易近似を使っていた。実機の Hz オフセットとは全然違う
- **修正**: YM2608 application manual Table 2-6 の milli-Hz 値 8×4×4 = 128 個を `s_anFmDetuneMilliHz[BLOCK][NOTE][FD]` 定数表に転写。`UpdateFmTickRate()` で master clock / sample rate を反映して `m_anFmDetunePhaseInc[BLOCK][NOTE][FD]` (16.16 fixed point) を再計算。`RecomputeFmOperatorPhaseInc()` は KSR と同じ N4/N3 式で Note を引き、`btDt` の bit 2 を sign として適用
- **注意**: manual の値は master = 8 MHz 時。それ以外のクロックでは `master / 8e6` で線形スケーリング (チップの phase generator が master clock に直接比例するため)

### 残課題 (v1.0.2 時点)

v1.0.2 で Operator output 14-bit 化・modulation `>> 1`・feedback `>> (10-FB)`・envelope rate 一律 4x 低速化が入り、fmgen との A/B 比較で「今までで一番近い」音色に到達。残るのは decap 由来 LUT が必須となる領域:

- **Attack curve**: `(env >> 4) + 1` は近似。実機 curve table と微妙に違うが、聴感上の差は小さい
- **Envelope rate の段差**: 現状は `(add * 65536) >> shift` の平均化 + 一律 4x 低速化。実機は段付き (rate ごとに tick イベントが離散的に発火) で、ピアノの初期減衰などで微妙な質感差が残る可能性あり
- **LFO 系 ($22, $B4–$B6 の AMS/PMS)**: YM2203 では未定義のため対象外 (OPNA only)

さらに詰めるなら YM2608 application manual の attack curve table・envelope rate の shift/add 分解表を一次資料として深掘りし、個別 rate の経験的 fit (fmgen 録音との FFT 差分解析) で詰めるのが次のステップ。ただし本リポジトリのライセンス方針上 decap 由来コード参照は不可。

## ライセンス上の自衛策 (本リポジトリ方針)

X88000 はフリーライセンスで配布されており、他プロジェクトのコードによる汚染は厳禁です。Phase C の実装にあたっては:

1. **既存の FM 音源コード (ymfm / fmgen / MAME / Game_Music_Emu / 等) は一切参照しない**。アルゴリズムを思い出すために眺めることもしない
2. **定数テーブルもコピーしない**。sin / exp / エンベロープレート / DT 値などはすべて `Initialize()` 内の数式から導出する
3. 仕様 (レジスタアドレス、ビット配置、計算式) は **事実情報** であり著作権の対象外。本ドキュメントの式や表をコメントとしてソースに引用することは問題なし
4. 他者の解説テキスト (Wikipedia 等) の **逐語訳** はしない。本ドキュメントに書かれた解説はオリジナルの言い回しで書くこと
5. 分からない箇所は「データシートを見る」「自分で実験する」で対応し、安易に他コードを覗かない

これに準拠することで、X88000M 全体のフリーライセンス互換性を維持します。

## まとめ

YM2203は3チャンネルFM＋3チャンネルSSG＋ノイズ発生器を備えた低コストの音源ICです。4オペレータ構成による多彩なアルゴリズム、独立周波数設定可能な第3チャンネル、2つの汎用タイマおよびI/Oポートにより、単体でも高機能なサウンドエンジンとして機能します。エミュレータを実装する際は、PSG互換性・レジスタマップ・タイマ処理・クロック分周および3チャンネルの特殊モードを正しく理解し、外付けDACとの接続まで含めて設計する必要があります。本レポートは著作権を侵害しない範囲で技術仕様をまとめたものなので、詳細な信号波形や回路図が必要な場合はオリジナルのデータシートを参照してください。
